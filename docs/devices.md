# iPad・Androidでの利用と検証

## 対象

特定の機種に限定せず、更新されたiPadのSafari、AndroidのChromeを主な対応対象にします。今回の変更はPWAの対応であり、App Store・Google Play向けのネイティブアプリではありません。古いOS・古いブラウザの全バージョン対応を保証するものではありません。

## ホーム画面への追加

### iPad

1. SafariでアプリのURLを開き、許可されたGoogleアカウントでログインします。
2. Safariの共有メニューから「ホーム画面に追加」を選びます。「Webアプリとして開く」がある場合は有効にします。
3. 追加したアイコンから開きます。必要に応じてログインし、この起動方法でも教材とオフライン利用期限を確認します。
4. 別の端末の教材を使う場合は「教材のアップロード」→「クラウドと同期」から、クラウドの教材を端末へ復元します。

Safariの表示とホーム画面からの起動では、保存状態がそのまま共有されることを前提にしません。アイコンから起動した側でオンラインの初回準備をしてください。iPadがMacのようなUser-Agentで動作する場合も、タッチ機能との組み合わせで追加案内を表示します。

ホーム画面への追加方法とstandalone表示の仕組みは、[WebKitの説明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)と[Safari 26の説明](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)を参照してください。

### Android

1. Chromeでアプリを開き、許可されたGoogleアカウントでログインします。
2. ホームの「この端末のホーム画面に追加」を開きます。ブラウザがインストール可能と判断した場合は「アプリをインストール」ボタンが表示されます。
3. ボタンがない場合はChromeのメニューから「アプリをインストール」または「ホーム画面に追加」を選びます。
4. アイコンから起動し、必要な教材を同期・復元して、オフライン利用期限を確認します。

インストールの確認画面はブラウザが管理します。アプリから強制表示できるものではありません。実装は[Chromeチームのインストール案内](https://web.dev/articles/customize-install)に沿い、インストールイベントの一度だけの使用と参照の解放を行います。

## 今回の変更

- タブレットでは最大1100pxまで表示領域を使い、長い本文は読みやすい幅に制限。
- 縦・横・分割表示、小型スマホで、見出しと操作ボタンの折り返しを調整。
- 横向きのスマホでは問題表示の余白を縮め、確認・戻る操作を画面に収める。
- 画面の安全領域を使った余白と、スクロールできるメニューを追加。端末風の装飾ホームバーを除去。
- Visual Viewportの高さに追従。ピンチズーム中はレイアウトの縮小を行わず、ネイティブの拡大操作を優先。
- 入力欄は16px以上、タッチ端末の主要ボタンは44px以上に調整。
- 本文で横スクロールとピンチ操作を許可し、表・図・数式を触った時にメニューの横スワイプと競合しないよう修正。
- アップロード画面の端を触った時に、現在のコンテンツを参照できずエラーになる経路を修正。
- ホーム画面への追加案内、Android等で利用可能なインストールボタン、Apple向けの表示メタ情報を追加。縦横の向きは固定しない。
- AbortSignal.timeoutがない場合の通信期限処理を追加。応答本文の読み込みにも期限を適用。

## 自動検証（2026-11-07）

Linux上のPlaywright 1.64.1、WebKit 27.2、Google Chrome 147.0.7727.55を使用。実OS・実機ではなく、ブラウザの画面サイズとタッチ入力を設定して検証しています。

| 想定 | エンジン | CSSピクセル | 結果 |
| --- | --- | --- | --- |
| iPad 縦 | WebKit | 834 × 1194 | 合格 |
| iPad 横 | WebKit | 1194 × 834 | 合格 |
| iPad 分割表示相当 | WebKit | 375 × 1024 | 合格 |
| Android スマホ | Chromium | 412 × 915 | 合格 |
| Android 横 | Chromium | 915 × 412 | 合格 |
| Android 小型画面 | Chromium | 320 × 568 | 合格 |
| Android タブレット | Chromium | 1280 × 800 | 合格 |

各サイズでホーム表示、画面のはみ出し、メニュー開閉、保存先選択、実際のMarkdownファイル読み込み、数式とMermaid描画、5段階の赤シート、タッチによる解答ボタン操作、ネットワーク遮断後の再起動と保存済み教材の表示を確認しました。

Android相当の4サイズでは、CDPからタッチイベントを送信し、表の横スクロールと空白部分の上・下スワイプによる解答の表示・非表示も確認しました。WebKitではタップとキーボードによる位置調整を確認しています。iPadのデスクトップ形式の端末情報での追加案内、タイムアウトAPIがない場合の本文読み込み中断、合成したインストールイベントの一度だけの使用も検証しました。

キーボード表示時の確認は、利用可能な領域を狭めるリサイズテストです。OSのソフトウェアキーボードを再現するものではありません。実際のホーム画面追加、Google OAuthの外部画面との行き来、機内モード、画面の切り欠き・ステータスバー、Apple Pencil、ブラウザ内アプリ、長時間バックグラウンド滞在、大容量教材は実機での確認が必要です。

既存の機能テストとメモリテストも合格しています。メモリテストでは140回の教材切り替え後、対象の画像URLと閉じた教材の描画要素は0件でした。

## 再実行

```sh
python3 -m venv .venv-tests
.venv-tests/bin/pip install -r tests/requirements.txt
.venv-tests/bin/python -m playwright install webkit
# Linuxで必要な場合は、管理者の手順に従ってWebKitの依存ライブラリを導入する
.venv-tests/bin/python -m playwright install-deps webkit
.venv-tests/bin/python tests/run_devices.py --screenshots work/devices
```

Chromiumのテストは既存のChromeを使用します。標準パスが異なる場合は`CHROME`に実行ファイルを指定します。WebKitだけ／Chromiumだけの実行は`--engine webkit`／`--engine chromium`です。テスト用WebKitを独自のライブラリ環境から実行する場合は`REDSHEET_WEBKIT_EXECUTABLE`で実行ファイルを指定できます。

PythonとPlaywrightはテスト用で、Cloudflareへの配布には含めません。従来どおりビルドやnpm installは不要です。
